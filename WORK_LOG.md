## 2026-11-25 — Этап 0a: техническая разведка API hh.ru и Stepik

### Что сделано

Изучена официальная документация и выполнены пробные запросы к API из рабочей среды.

- hh.ru: OpenAPI-спецификация (`https://api.hh.ru/openapi/specification/public`),
  репозиторий документации `hhru/api` (README, `docs/vacancies.md`, `docs/FAQ.md`,
  `docs/authorization.md`, `docs/authorization_for_application.md`, `docs/errors.md`).
- Stepik: Swagger-документация `https://stepik.org/api/docs/` (машинночитаемую
  спецификацию получить не удалось), поведение API проверено серией живых запросов.
- Дополнительно просмотрена документация SuperJob API и предпринята попытка
  проверить API «Работа России» (trudvsem).

### Результаты

**hh.ru**

- Поиск вакансий и полная карточка вакансии без токена недоступны: `GET /vacancies`
  и `GET /vacancies/1` возвращают `403 forbidden`. Спецификация подтверждает:
  без токена после первого запроса требуется прохождение капчи.
- Для доступа необходимо приложение на dev.hh.ru и токен приложения
  (OAuth2, `grant_type=client_credentials`, заголовок `Authorization: Bearer`).
- Справочники (`/professional_roles`) доступны анонимно.
- Ограничения выдачи: `per_page` не более 100, глубина результатов не более 2000
  на один запрос; `area=113` — Россия; есть `professional_role`, `period`,
  `date_from`, `date_to`, `search_field`, язык запросов в `text`.
- Заголовок `User-Agent` обязателен; часть значений в чёрном списке
  (тестовый UA с доменом `example.com` получил `bad_user_agent: blacklisted`).
- Структура ответов: поиск отдаёт короткую карточку и `snippet`
  (`requirement`, `responsibility`) без `key_skills` и без полного описания;
  полное описание (HTML) и `key_skills` (до 30 навыков) — только в карточке
  `/vacancies/{id}`.
- Rate limit в документации явно не зафиксирован.

**Stepik**

- OAuth-токен для нужных методов не требуется: `/api/courses?search=...`,
  `/api/courses/{id}`, `/api/courses?ids[]=...`, `/api/sections`,
  `/api/units`, `/api/lessons`, `/api/search-results` отвечают `200` анонимно.
- `/api/courses` без фильтров возвращает пустой список; с `is_public=true` —
  корректные данные.
- `/api/search-results` ограничен 200 результатами на запрос (10 страниц по 20).
  `/api/courses?search=...` пагинируется глубже (проверено до 20-й страницы).
- Публичный каталог листается: `is_public=true&page=1000` отдаёт данные,
  `page=5000` — пусто.
- Пакетная выборка по `ids[]` работает для курсов, секций, юнитов и уроков.
- Поля курса включают: `title`, `summary`, `description` (HTML), `requirements`,
  `target_audience`, `language`, `is_paid`, `price`, `currency_code`,
  `learners_count`, `time_to_complete`, `difficulty`, `tags`, `lessons_count`,
  `review_summary`, `is_archived`, `is_public`, `canonical_url`, `slug`,
  `update_date`, `sections`, а также `acquired_skills` и `acquired_assets`.
- Цепочка получения заголовков уроков подтверждена:
  `course.sections` → `sections[].units` → `units[].lesson` → `lessons[].title`.
- Rate limit в документации не зафиксирован; требуется консервативная задержка
  между запросами.

**Альтернативные источники**

- «Работа России» (trudvsem): API из рабочей среды недоступен (соединение не
  устанавливается, страница документации отдаёт HTTP 460). Статус не подтверждён.
- SuperJob API: поиск вакансий не требует пользовательской авторизации, но
  требует заголовок `X-Api-App-Id` в каждом запросе; лимит 120 запросов/мин,
  до 500 сущностей на список; структурированного поля `key_skills` нет.

### Принятые решения

- Основной источник вакансий — hh.ru, так как только он даёт размеченное
  работодателем поле `key_skills`, что позволяет валидировать этап извлечения
  навыков относительно «золотого» поля.
- Единственный источник курсов на данном этапе — Stepik.
- SuperJob и «Работа России» в разработку не берутся.
- Порядок работ скорректирован: этап 0b (каркас и схема БД) → сбор курсов Stepik
  → сбор вакансий hh.ru по получении токена. Причина: регистрация приложения hh
  может занимать до 15 рабочих дней, простой недопустим.
- Кэш сырых ответов API переводится из «желательного» в обязательный элемент
  архитектуры: сбор вакансий требует двух запросов на запись, повторный сбор
  без кэша недопустим.
- Сбор курсов выполняется через `/api/courses?search=...` (глубокая пагинация),
  а не через `/api/search-results` (жёсткий предел 200).

### Проблемы и открытые вопросы

- Регистрация приложения hh.ru — на критическом пути, срок до 15 рабочих дней.
  Заявка ещё не подана.
- Неизвестно, какая доля вакансий hh имеет непустой `key_skills`; влияет на
  стратегию извлечения навыков (этап 3).
- Неизвестно, какая доля курсов Stepik заполняет `acquired_skills`; влияет на
  подход к определению компетенций курса (этап 6).
- Не установлена семантика поля `review_summary` (рейтинг или иное).
- Фактическое число релевантных курсов Stepik по выбранным ролям не измерено;
  при нехватке данных потребуется пересмотр списка ролей.
- Rate limit обоих API документально не зафиксирован — параметры задержек
  определим эмпирически при сборе.

## 2026-11-25 — Заявка на приложение hh.ru: анализ формы регистрации

### Что сделано

- Изучена форма регистрации приложения на dev.hh.ru.
- Проверена OpenAPI-спецификация на предмет требований авторизации для методов
  поиска вакансий.

### Результаты

- Форма предлагает только два варианта аудитории: «Только сотрудники работодателя»
  и «Сотрудники нескольких работодателей». Варианта для исследовательского
  проекта нет.
- На форме указано: поддержка API для соискателей прекращена 15.12.2025.
- В OpenAPI-спецификации глобальная авторизация — OAuth2 с потоками
  `authorizationCode` и `clientCredentials`, scope не заданы. Токен приложения
  технически пригоден для методов API, включая поиск вакансий.
- Контакт поддержки API: `api@hh.ru` (указан в футере dev.hh.ru и в разделе
  `info.contact` спецификации).

### Принятые решения

- Заявку пока не подавать: выбранный наугад вариант аудитории противоречил бы
  описанию проекта и повышал риск отказа.
- Сначала направить в `api@hh.ru` уточняющий запрос: допустима ли регистрация
  исследовательского приложения, какой вариант аудитории выбрать, доступен ли
  `client_credentials` после 15.12.2025, допустимо ли хранить снимок вакансий.

### Проблемы и открытые вопросы

- Ответ поддержки не гарантирован, срок ответа неизвестен.
- При отказе потребуется запасной источник данных о вакансиях: SuperJob,
  «Работа России» или публичный датасет.

### Далее

1. Отправить письмо в `api@hh.ru`.
2. Этап 0b: каркас проекта, конфигурация, схема БД, CLI.
