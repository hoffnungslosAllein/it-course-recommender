# Заявка на приложение hh.ru — подготовленные материалы

Материалы для заполнения формы регистрации на https://dev.hh.ru/admin.
Поддержка ответила 2026-11-26: заявку можно подавать в стандартном порядке.

## Ответ поддержки (2026-11-26)

1. В блоке «Приложением будут пользоваться» выбирать **«Сотрудники нескольких
   работодателей»**.
2. Токен приложения (`client_credentials`) использовать допускается.
3. Порядок регистрации стандартный, через https://dev.hh.ru/admin.
4. Ограничений на хранение данных нет. Но если вакансии отображаются другим людям,
   их необходимо актуализировать (изменять/удалять) в течение двух часов.

**Следствие для проекта:** вакансии используются только как внутренние данные для
построения профиля компетенций и **не отображаются пользователям**. Это снимает
обязательство по двухчасовой актуализации; формулировки в полях формы приведены
в соответствие.

## Контекст

На форме указано, что поддержка API для соискателей прекращена 15.12.2025.

### Информация о создателе приложения

> Физическое лицо. Сиротин Евгений, студент выпускного курса. Приложение
> разрабатывается как некоммерческий исследовательский проект в рамках выпускной
> квалификационной работы.

### Кто будет его использовать

> Автор проекта и ограниченный круг пользователей в учебных целях: студенты и
> преподаватели. Публичного доступа не предполагается, коммерческой эксплуатации
> нет. Вакансии используются только как внутренние данные для построения профиля
> компетенций и не отображаются пользователям приложения.

### Какие задачи должно решать приложение

> Анализ требований рынка труда к ИТ-специальностям на основе открытых данных о
> вакансиях и подбор образовательных курсов под эти требования. Приложение
> собирает публичные вакансии, извлекает профессиональные навыки, строит
> взвешенный профиль компетенций ИТ-роли и сопоставляет его с компетенциями,
> которые формируют образовательные курсы.

### Функциональные возможности и используемые методы API

> 1. Поиск вакансий по запросу с фильтрами по региону и профессиональной роли —
>    `GET /vacancies` (параметры `text`, `area`, `professional_role`, `per_page`,
>    `page`).
> 2. Получение полной карточки вакансии, включая описание и список ключевых
>    навыков — `GET /vacancies/{id}`.
> 3. Загрузка справочников для нормализации данных — `GET /professional_roles`,
>    `GET /areas`, `GET /dictionaries`.
> 4. Построение профиля компетенций ИТ-роли и ранжирование образовательных курсов
>    выполняется локально, без обращения к API.
>
> Доступ только на чтение. Методы работы с резюме, откликами, перепиской,
> публикацией и редактированием вакансий не используются. Персональные данные не
> запрашиваются. Полученные вакансии не отображаются пользователям приложения:
> они используются исключительно для расчёта профиля компетенций ИТ-роли.

## После одобрения

- `client_id` и `client_secret` — в кабинете https://dev.hh.ru/admin.
- Токен: `POST https://api.hh.ru/token`, `grant_type=client_credentials`.
  Не чаще одного раза в 5 минут (иначе `403 forbidden`, `app token refresh too early`).
- Секреты — в `.env` (уже в `.gitignore`), в репозиторий не попадают.
