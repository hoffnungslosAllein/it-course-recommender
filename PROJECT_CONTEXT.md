## 1. Проект

**Тема ВКР:** «Программная реализация алгоритма рекомендации образовательных курсов
для ИТ-ролей».

**Цель:** работающий прототип, который принимает ИТ-роль и формирует список
образовательных курсов с оценкой релевантности, покрытыми и непокрытыми
компетенциями и объяснением причин рекомендации.

**Логика работы:** сбор вакансий → очистка → извлечение и нормализация навыков →
профиль компетенций роли → сбор курсов → компетенции курсов → сопоставление →
ранжирование → экспериментальная оценка.

**Задачи ВКР (9):** анализ подходов; сбор и обработка вакансий; извлечение и
нормализация навыков; профиль роли; компетенции курсов; алгоритм сопоставления;
алгоритм рекомендации; программная реализация; экспериментальная оценка.

## 3. Проверенные факты об API

### hh.ru

- Поиск вакансий и карточка без токена недоступны: `403 forbidden`.
  Нужен токен приложения (OAuth2, `client_credentials`).
- Регистрация приложения: https://dev.hh.ru/admin, срок до 15 рабочих дней.
- `per_page` ≤ 100; глубина выдачи ≤ 2000 результатов на запрос.
- `area=113` — Россия; есть `professional_role`, `period`, `date_from`,
  `date_to`, `search_field`, язык запросов в `text`.
- `User-Agent` обязателен, часть значений в чёрном списке.
- Поиск отдаёт короткую карточку + `snippet` (без `key_skills` и полного описания).
- Полное описание (HTML) и `key_skills` (до 30) — только в `GET /vacancies/{id}`.
- Справочники (`/professional_roles`, `/areas`, `/dictionaries`) доступны анонимно.
- Rate limit документально не зафиксирован.
- Токен: `POST https://api.hh.ru/token`, `grant_type=client_credentials`,
  `client_id` и `client_secret`. Ответ `200` содержит только `access_token`
  и `token_type: bearer`; поля `expires_in` нет.
- Повторный запрос токена раньше чем через 5 минут:
  `403 app token refresh too early`. Токен нужно кэшировать.

### Stepik

- Авторизация не требуется для: `/api/courses?search=...`, `/api/courses/{id}`,
  `/api/courses?ids[]=...`, `/api/sections`, `/api/units`, `/api/lessons`,
  `/api/search-results`.
- `/api/courses` без фильтров отдаёт пустой список; нужен `is_public=true`.
- `/api/search-results` ограничен 200 результатами на запрос.
- `/api/courses?search=...` пагинируется глубже; каталог листается до ~1000 страниц.
- Пакетная выборка по `ids[]` работает для курсов, секций, юнитов, уроков.
- Цепочка заголовков уроков: `course.sections` → `sections[].units` →
  `units[].lesson` → `lessons[].title`.
- Полезные поля курса: `title`, `summary`, `description`, `requirements`,
  `target_audience`, `language`, `is_paid`, `price`, `learners_count`,
  `time_to_complete`, `difficulty`, `tags`, `lessons_count`, `review_summary`,
  `acquired_skills`, `sections`.
- Rate limit документально не зафиксирован.

## 4. Структура проекта

```
skillrec/
  cli.py           командный интерфейс, 6 подкоманд
  config.py        загрузка и проверка config.yaml
  db.py            подключение к SQLite, init-db
  schema.sql       схема БД версии 1
  collect/         сбор данных (этапы 1–2)
  extract/         извлечение навыков (этап 3)
  profile/         профиль роли (этап 3)
  match/           сопоставление (этап 4)
  recommend/       ранжирование (этап 4)
  eval/            оценка (этап 5)
data/
  raw/             сырые ответы API, в git не попадают
  db/              файл SQLite, в git не попадает
  dictionary/      словарь навыков (этап 3)
tests/             тесты конфига и БД
config.yaml
pytest.ini
```

Схема БД: 13 таблиц (`runs`, `roles`, `role_queries`, `vacancies`, `skills`,
`skill_aliases`, `vacancy_skills`, `courses`, `course_skills`, `role_profiles`,
`recommendations`, `eval_labels`, `eval_metrics`). Версия хранится в
`PRAGMA user_version`. Первичный ключ вакансии и курса — `source:source_id`.
Стадии, влияющие на результаты, пишут `run_id` с хэшем параметров.

Стиль кода: простой, без лишних абстракций — конфиг в виде словаря, проверки
отдельными функциями, минимум вспомогательных конструкций. Причина: код должен
быть объясним построчно на защите.
